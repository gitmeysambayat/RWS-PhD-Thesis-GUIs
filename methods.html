A guide to the demonstrations

Methods and use

Use these tools to inspect the circular reduced web section (RWS) study, compare finite element (FE) response and examine machine-learning (ML) predictions. This guide explains what the browser does and how to interpret its outputs.

Start with one controlled comparison

  1. Reduced Web Section Explorer. Choose IPE270, S235 and the span-to-depth setting 6, then select C00: opening diameter/depth 30% and opening distance/depth 60%. Click Add curve to retain it, then Select C100 (Full section) to compare with the no-opening reference. Read the backbone curve and column-face indicators together.
  2. Dynamic Radar Plot. Filter to the same profile, grade and span-to-depth setting, then adjust the response ranges and Top N. Compare trade-offs in energy, moment retention, degradation and column-face response. The ranking helps shortlist existing configurations for an optimisation study.
  3. Cumulative Energy Dissipation. Select the IPE270/S235/span-setting-6 batch, click Clear all, select C00, then click Plot selected. Include C100 when comparing the absolute curves with the full-section baseline, or examine the normalised cumulative-energy response.
  4. FE and ML Backbone Prediction. Inspect C00 in FE mode, then switch to ML prediction mode and vary an input between database settings. Compare the predicted response with FE data at matching database points; an exact FE overlay appears only at those points.

Keep the case ID and settings with any exported plot. This makes a comparison traceable to its stored reference rather than just a screenshot.

Dataset coverage

The Explorer and ML interface share 7,575 stored FE-derived records: 7,500 circular-opening cases and 75 full-section references. The embedded export is dated 17 February 2026.

What each tool does

FE explorer: select and compare stored results

The controls select exact rows in an embedded dataset. JavaScript renders the backbone curves and loads case-labelled von Mises and equivalent plastic strain (PEEQ) contour images. Add curves to compare cases or export the plot as SVG. The browser does not launch an Abaqus analysis.

Radar comparison: screening to support optimisation

The radar tool supports optimisation studies by filtering existing configurations against chosen response ranges and ranking the remaining candidates by polygon area. It normalises the stored summaries using fixed global ranges, making trade-offs visible across the selected response measures. Its six spokes represent column-face PEEQ and von Mises indicators, normalised energy, strength degradation, moment at 0.06 rad relative to the full section, and peak moment relative to the full section.

The selected favourable direction is shown outward. A large polygon depends on those directions, scales and spoke order; it does not establish an optimum or design qualification. The CSV command exports all cases passing the filters, not only the displayed Top N, and retains the original download-password prompt.

Energy viewer: compare saved cyclic-response histories

The viewer plots saved cumulative-energy arrays for selected cases and their full-section references. It offers the stored absolute scale (labelled kJ) and per-cycle normalisation by the corresponding full-section history. It does not integrate raw hysteresis signals in the browser. Comparisons should use compatible loading sequences.

FE–ML comparison: run the exported model

The page loads the supplied xgb_model.json and evaluates its 400 trees in JavaScript. Nine input features produce 21 normalised moment ordinates, which are scaled by section plastic moment to form a predicted backbone. This is browser-side inference, including for intermediate inputs within the controls.

At an exact database point, the interface can overlay the stored FE curve and associated contours. Between those points, an ML prediction does not create a new FE result. A full-database benchmark measures agreement with the embedded references; the repository does not include the training pipeline or split information needed to identify an independent test set.

Interpreting the outputs

The tools support research exploration of this circular-RWS study. Moment-retention and rotation thresholds are individual screening measures, not evidence of formal connection prequalification or a substitute for the applicable modelling and design checks. FE agreement is distinct from experimental validation.

Span notation and material inputs

The interface uses a span-to-depth control labelled L/h; the exported model names that feature 2L/h. The browser passes the stored value unchanged. The original half-span/full-span definition needs to be checked against the research methodology before mapping an external geometry to this input. The model uses nominal grade strength as a feature; the FE export also contains stored material-strength values, which need not equal the nominal grade.

Field quantities and absolute energy scales

Some exported field quantities are stored summary indicators, and their raw scale or aggregation is not fully documented here. Use their stated normalisations for comparative interpretation; do not assume a raw indicator is a pointwise stress or strain without checking the extraction definition. The radar’s absolute energy summary and the energy viewer’s absolute histories are not reconciled by the repository documentation. Their matching normalised trends do not establish a common absolute scale.

Benchmark metrics and model scope

Database-wide error measures describe the supplied records and model export. They do not establish held-out accuracy, training independence or performance beyond the studied domain. When an ultimate-rotation value is shown as a lower bound because a 20% strength drop was not reached within the available curve, read it as a finite-window result; an aggregate rotation error can include such censored values. The repository packages the deployed model and outputs, not the full FE-generation, training or experimental-validation workflow.
